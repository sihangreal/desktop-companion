## 1. 背景与问题

现有 FRAC 系壁纸（Wallpaper Engine 网页壁纸）是**纯预设**的：衣橱、对白、动作全部写死在 `catalog.js` / `dialogue.json` 里，用户只能选，不能聊。

用户手上有 DeepSeek 的 ASR / TTS / LLM 三套 API，希望得到"能与桌面角色实时对话"的陪伴程序，并且**保留现有壁纸的衣橱/换装模式**：说话时她是活的，不说时可以挑衣服。既有素材的形态就是"每套一段视频，循环播放"，视觉状态只是叠加在画面上的特效，不额外制作素材。

Wallpaper Engine 沙箱无法提供原始麦克风与音频控制，因此目标形态定为**独立桌面常驻程序**（壁纸皮肤留作后续可选形态）。

**核心价值判断**：决定好不好用的不是功能数量，而是**延迟**与**打断**。端到端若稳定超过 3 秒，等价于失败。而供应商能力（见 §9.5）会把延迟压到 2–3 秒区间，因此本规格的时间预算按"供应商真实能力"分配，不按理想值分配。

## 2. 目标与非目标

### 2.1 目标（P0 必须达成）

- G-1 按住热键说话，松开后角色用中文语音回应，可连续多轮。
- G-2 端到端延迟 P50 ≤ 2.5s（SC-001，理由见 §9.5）。
- G-3 角色说话期间用户开口，能立即打断。
- G-4 角色有稳定人格，不因多轮对话而出戏。
- G-5 保留衣橱模式：每套装扮一段视频、循环播放；可浏览与切换，切换即刻生效并记住。
- G-6 静置时对系统负担可控（NFR-002，含省电模式）。

### 2.2 非目标

| 编号 | 非目标 | 原因 |
|---|---|---|
| NG-1 | 视觉理解（看屏幕、识别窗口内容） | 成本与隐私代价高 |
| NG-2 | Live2D / 3D 角色 | P0 用视频状态机验证体验 |
| NG-3 | 多角色同时存在（多个不同"人"） | 单角色 + 多套装扮；角色唯一 |
| NG-4 | 手机端 / 网页端 | 与桌面常驻形态冲突 |
| NG-5 | 本地模型部署 | 用户使用云端 API；适配层预留 |
| NG-6 | Wallpaper Engine 壁纸形态 | P2 之后评估，见 §9.3 |
| NG-7 | 主动发起对话 | 用户明确不需要（D-4） |
| NG-8 | 语音克隆 / 自训练音色 | 交给供应商 |
| NG-9 | 免提 / 唤醒词 | 用户明确不需要（D-1） |
| NG-10 | 多语言（含中英混说专项优化） | 用户明确只做中文（D-2） |
| NG-11 | macOS / Linux | 用户明确不需要（D-5） |
| NG-12 | 语速/音调调节 | 供应商不支持（TTS 无此参数，§9.5） |
| NG-13 | 精细口型（viseme） | 供应商不返回音素时间戳（§9.5） |
| NG-14 | 为每套装扮单独制作聆听/说话视频 | 用户明确不需要（D-12） |

## 3. 用户场景

优先级：P1 = 不实现则产品不成立；P2 = 显著影响留存；P3 = 加分项。

### US-1 初次配置（P1）

首次启动，填入 DeepSeek API Key，点"测试连接"，三行绿灯（LLM / ASR / TTS）后即可对话。**≤ 3 分钟，无需改配置文件、无需命令行。**

### US-2 一次对话（P1）

按住 `Ctrl+Shift+Space` 说"今天有点累"，松开。角色进入"聆听"态（画面加一圈光晕）→ 约 1 秒后气泡先出现文字 → 语音紧接着响起："那就别硬撑了，靠一会儿？"。她说话时画面在正常循环播放。

### US-3 打断（P1）

她正在说一句 8 秒的话。用户中途开口，**语音 300ms 内停止**，角色转聆听态。ASR 非流式（§9.5），打断只损失播放，不损失已生成的文本。

### US-4 关系连续性（P2）

第二天问她"还记得我昨天说什么吗"，她答得出"你说加班到很晚"。用户可查看并删除记忆条目，**不能改写正文**（D-6）。

### US-5 换装（P1）

用户点开衣橱，浏览三个分组、翻页、点封面换装。换装后立即以新外观继续对话，**记忆与关系不重置**。当前装扮重启后保持；她还知道"我现在穿的是哪套"（D-15）。

### US-6 失效降级（P1）

断网、密钥错误、额度耗尽、内容审核拒绝（TTS 400）时，她说一句预设兜底台词（来自旧壁纸对白库，D-16）或给出可读提示，程序不崩、不弹技术错误。

### US-7 桌面共存（P1）

置顶于普通窗口之上、不遮挡全屏应用（P2）、可拖动并记住位置、托盘一键隐藏、可切省电模式。

## 4. 术语

| 术语 | 定义 |
|---|---|
| Turn（轮） | 一次完整交互：用户音频 → ASR 文本 → 回复文本 → TTS 音频 |
| 打断（Barge-in） | 用户在她说话期间开口，系统停止播放并取消在途请求 |
| 角色卡（Persona） | 唯一角色的人格设定：名字、称呼、性格、语气、禁忌、口癖 |
| 装扮（Look） | 角色的外观单元：一段循环视频 + 封面 + 所属衣橱 |
| 衣橱（Wardrobe） | 装扮的分组与浏览单位（1–3 个） |
| 状态叠加 | 视频常驻循环播放；四种视觉状态只叠加特效，不切换素材（§9.4） |
| 半双工门控 | 播放语音期间不拾音（无 AEC 时的保底策略） |
| 适配器（Adapter） | 面向单类外部能力的抽象接口：ASR / LLM / TTS |

## 7. 外部接口契约

只有 TTS 和 LLM 是流式，**ASR 不是**。实现须容忍供应商参数裁剪。

### 7.1 ASR（非流式，整段提交）

```
端点：POST https://api.deepseek.com/v1/tools/asr
请求：multipart/form-data，file 字段
格式：16-bit PCM WAV 或 Ogg Opus（按内容判断）
采样率：8000/16000/22050/24000/32000/44100/48000
声道：单声道或双声道（仅识别左声道）
上限：8 MiB、120 秒、上传须在 10 分钟内完成
语言：无参数，自动识别
响应：{ request_id, text, duration_ms }
错误：400 / 408 / 413 / 429 / 503 / 504
```

**设计后果**：无法边说边识别，必须等松手。客户端须保证音频 ≤ 60s 且远小于 8 MiB（16k/16-bit 单声道 = 32 KB/s）。

### 7.2 LLM

```
端点：POST https://api.deepseek.com/chat/completions（OpenAI 兼容，SSE 流式）
输出约定：首行为行内标记 [emotion:xxx]，其后为纯口语正文
解析：标记必须剥离，绝不送 TTS；缺失时按 neutral 处理
```

### 7.3 TTS

```
方式 A（P0）：POST https://api.deepseek.com/v1/tools/tts
  body: { text, voice_id: stella|tide, format: pcm, filter_markdown: true }
  响应体流式返回音频；pcm = 24kHz / 16-bit / 单声道（无容器头，可直接推播放器）
  上限：单次 10,000 计费字符、请求体 64 KiB、单次最多 30 分钟音频
方式 B（P1）：wss://api.deepseek.com/v1/tools/tts?voice_id=&format=pcm
  发 {"event":"text","text":"..."} … {"event":"finish_text"}；二进制帧为音频
  结束消息 {"event":"finish","code","message"}
  限制：60s 无文本超时；单会话 ≤ 30 分钟 / 10,000 字符
通用：不支持语速/音调；不支持断点续传；无 viseme
错误：400（无可朗读文本 / Content Exists Risk）、429、503、504；已开始返回后失败会中途断开
限速：单账号 50 并发
```

**设计后果**
- 无语速参数 → 语感只能靠标点断句（NG-12）。
- 无音素时间戳 → 无法 viseme，口型靠素材（NG-13、D-9）。
- `format=pcm` 优于 `wav`（无头、定长帧），P0 选 pcm。
- 审核 400 是确定性失败，重试同句无效，必须换句（FR-036）。

### 7.4 通用约束

- 所有请求可取消（打断、关窗、超时）。
- 超时 + 有限重试：幂等请求最多 2 次、指数退避；**审核类 400 不重试**。
- 鉴权失败 / 额度耗尽视为终止性错误，不重试，直接降级。

## 9. 技术约束与选型

### 9.1 目标形态

独立桌面常驻程序，单实例，托盘常驻；中文界面；仅 Windows x64。

### 9.2 技术栈：Rust + Tauri 2（系统 WebView2）

| 层 | 选型 | 理由 |
|---|---|---|
| 应用外壳 | Tauri 2 | 原生 Rust 后端 + 系统 WebView2；产物 ~15MB，无常驻 Chromium |
| 核心逻辑 | Rust / tokio | 音频、网络、状态机、存储全在 Rust 侧 |
| 界面层 | WebView2 + TypeScript | 视频纹理、CSS 动画、字幕排版成本最低 |
| 音频 | WASAPI（采集 + 渲染） | 仅 Windows，低延迟；本地完成 16k/24k 重采样 |
| 端点检测 | Silero VAD（ONNX / `ort`） | 中文短句判停优于能量阈值 |
| 回声消除 | P0 半双工；P1 评估 AEC3 | 见 R-3 |
| 存储 | SQLite（`rusqlite`） | 记忆、轮次、装扮元数据 |
| 密钥 | Windows 凭据管理器 | 满足 FR-071 |
| 日志 | `tracing` + 滚动文件 | 满足 NFR-008 |

**说明**：Tauri 不打包 Chromium，但界面层仍用系统 WebView2（Edge 内核）。若要彻底去 WebView，需切 `egui`/`iced`，工期约 ×3 且视频解码风险高。

**备选与落选**：Electron（内存/包体过大）／egui·iced（视频与排版全自建）／Slint（视频能力弱）／浏览器扩展（不能常驻、无全局热键）。

### 9.3 与 Wallpaper Engine 的关系

P0 不进入壁纸形态。P2 后若需要，采用"壁纸只画、进程听说"的拆分，壁纸经本地通道接收 `{text, audio, emotion, state}`。

### 9.4 播放与状态模型（关键设计约束）

**每套装扮只有一段视频，常驻循环播放。** 四种视觉状态不切换素材，只在同一画面上叠加特效：

| 状态 | 视频 | 叠加层 |
|---|---|---|
| 待机 | 循环播放（省电模式可暂停/降帧） | 无，或极轻呼吸缩放 |
| 聆听 | 循环播放 | 麦克风光晕 + 轻微高亮 |
| 思考 | 循环播放 | 呼吸加速 + 三点指示 |
| 说话 | 循环播放 | 音量包络驱动的整体轻微起伏 + 字幕气泡 |

约束与后果：
- **不需要**为每套额外制作聆听/说话视频（NG-14），121 套现有素材可直接复用。
- 视频始终在跑，因此省电模式（FR-079）是必要功能而非可选优化；待机资源阈值相应放宽（NFR-002）。
- 口型无法与语音同步（供应商无 viseme），只能做整体起伏；这是已知表现上限，须在交付说明中如实标注。
- `entry` 类型装扮可选择在 `freezeSec` 定格；默认 `loop` 类型不打断循环（FR-042）。

### 9.5 供应商能力与延迟/成本预算

| 能力 | DeepSeek 现状 | 影响 |
|---|---|---|
| ASR 流式 | **不支持**（整段） | 必须等松手，延迟 +0.5–1.0s；需硬限 60s |
| ASR 语言参数 | **不提供**（自动识别） | 不能强制 zh，需"非中文请重说"兜底 |
| TTS 流式 | 支持（HTTP 流 + WS） | 首句可早出声，P0 用 HTTP 流 |
| TTS 语速/音调 | **不支持** | NG-12；语感靠断句 |
| TTS viseme | **不提供** | NG-13；口型靠素材 |
| TTS 音色 | 2 个（stella / tide） | 默认 stella，与角色匹配（D-14） |
| 内容审核 | 400 `Content Exists Risk` | 必须换句重试（FR-036） |

**延迟预算（P50，ms）**

| 段 | 预算 | 说明 |
|---|---|---|
| 松手 → 编码 WAV | 40 | 16k/16-bit，60s 最大 1.9MB |
| 上传 + ASR | 700 | 3 秒语音；弱网按 1200 计 |
| LLM 首 token | 600 | 首句 ≤ 15 字 |
| LLM 到首个句号 | 300 | 切句用 |
| TTS 首包（24k PCM） | 400 | 首句 15 字 |
| 播放启动 | 60 | WASAPI |
| **合计** | **≈ 2100** | P90 按 4.0s 计 |

**成本预算（刊例价上限）**

| 项 | 单价 | 单轮用量 | 成本 |
|---|---|---|---|
| TTS | 3 元 / 万计费字符（汉字算 2 字符） | 60 汉字 = 120 字符 | ≈ 0.036 元 |
| ASR | 0.78 元 / 小时 | 3 秒 | ≈ 0.0007 元 |
| LLM | 按 token | 约 1.5k in / 100 out | ≈ 0.001 元 |
| **合计** | | | **≈ 0.038 元 / 轮** |

→ 100 轮/天 ≈ 3.8 元/天 ≈ 115 元/月。**TTS 占 95%**，所以"回复短"既是体验也是成本问题（FR-022、NFR-012）。

### 9.6 已知风险

| ID | 风险 | 影响 | 缓解 |
|---|---|---|---|
| R-1 | WebView2 运行时缺失 | 启动失败 | 检测 + 引导安装 Evergreen Bootstrapper |
| R-2 | 透明窗 + 视频硬解在部分驱动黑屏 | 视觉不可用 | FR-078 降级开关 |
| R-3 | 无 AEC，易自激回声 | 必须半双工 | 门控 + 耳机假设；P1 评估 AEC3 |
| R-4 | ASR 非流式，延迟下不去 | 体验上限受限 | 首句极短 + 早切句 + TTS 并行 |
| R-5 | TTS 审核误伤正常回复 | 突然没声音 | 换句重试 + 纯文字兜底 |
| R-6 | 素材体积约 930MB | 首启扫描慢 | 元数据缓存 + 按需加载 + 缩略图 |
| R-7 | 素材权利 | 分发风险 | 不随包分发（D-3） |
| R-8 | 循环播放导致 GPU 常驻 | 笔记本耗电/发热 | 省电模式（FR-079）+ 全屏时暂停（FR-051） |

## 11. 验收方法

### 11.1 延迟定义

端到端 = 用户松开热键（或 VAD 判停）→ **首个音频包开始出声**。分段记录：编码、上传、ASR、LLM 首 token、切句、TTS 首包、播放启动；差额记为"本地开销"。

### 11.2 验收门禁

- 每阶段跑通完整脚本：一次对话 + 一次打断 + 一次故障注入 + 一次换装。
- 不以"工具跑通"替代体验验收：**必须实际听语音、看状态切换**。
- 循环播放的接缝须逐个装扮肉眼确认；未实测项标注"未验证"，不得声称"流畅/无 bug"。
