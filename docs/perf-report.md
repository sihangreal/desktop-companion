## 2. 首声构成

```
LLM 首 token          711ms  ██████████
TTS 首包 + 等首句     716ms  ██████████
──────────────────────────────────────
首声                 1583ms  ██████████████████████
```

- 每轮平均切出 **1.5 段** TTS（32 段 / 21 轮）
- TTS 合成耗时是音频时长的 **0.56 倍**，即合成速度约为播放的 **1.8 倍**（>1 才不会断档）

## 4. 完整链路估算（P50）

> 对话测试是直接喂文本，**不含 VAD 与 ASR**；下表把这两段按实测值补上。

```
VAD 判停         +  700ms  →   700ms
ASR 识别         +  780ms  →  1480ms
LLM 首 token    +  711ms  →  2191ms
TTS 首包         +  716ms  →  2907ms
首声               2907ms（从用户说完算起）
```

## 5. 结论

1. 最大头是 **TTS 首包（810ms）**，其次 ASR（780ms）、LLM 首 token（711ms）。
2. TTS 合成耗时仅为音频时长的 0.56 倍，合成快于播放，正常不会断档。
3. **LLM 流式实际是一次性返回**：首 token 到流结束只差 1ms（P90 2ms），说明服务端把整段回复缓冲后一次吐出。
   因此「首句先切出来提前合成」的优化在本机没有收益，首声 ≈ LLM 全量输出 + TTS 首包。
4. 想进一步压低首声，只能动 LLM 首 token（换模型/压 prompt）或 TTS 首包（换更快的语音服务）。

> ASR 为独立基准：固定 4.24 秒音频、连续 5 次；其余为真实对话轮次。
