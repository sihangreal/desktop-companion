## 5. 完整链路估算（P50）

> 对话测试是直接喂文本，**不含 VAD 与 ASR**；下表把这两段按实测值补上。

```
VAD 判停         +  700ms  →   700ms
ASR 识别         +  806ms  →  1506ms
LLM 首 token    +  803ms  →  2309ms
TTS 首包         +  716ms  →  3025ms

```

## 6. 结论

1. 最大头是 **ASR（806ms）**，其次 LLM 首 token（803ms）、TTS 首包（767ms）。
2. TTS 合成耗时仅为音频时长的 0.59 倍，合成快于播放，正常不会断档。
3. **LLM 流式实际是一次性返回**：首 token 到流结束只差 1ms（P90 3ms），说明服务端把整段回复缓冲后一次吐出。
   因此「首句先切出来提前合成」的优化在本机没有收益，首声 ≈ LLM 全量输出 + TTS 首包。
4. 想进一步压低首声，只能动 LLM 首 token（换模型/压 prompt）或 TTS 首包（换更快的语音服务）。

> ASR 为独立基准：固定 4.24 秒音频、连续 5 次；其余为真实对话轮次。
